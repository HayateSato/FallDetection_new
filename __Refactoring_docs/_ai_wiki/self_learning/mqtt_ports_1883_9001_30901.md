# MQTT Ports — 1883, 9001, 8883, 30901, and 443

Each port serves a distinct purpose and a different caller. They all feed into the same
mosquitto pod, but via different paths through (or around) Traefik.

---

## One Traefik, multiple entrypoints

There is a single Traefik instance in the k3s cluster. It listens on multiple ports
simultaneously. Each port is an "entrypoint" in Traefik's terminology. Routes (IngressRoute,
IngressRouteTCP) declare which entrypoint they belong to — a connection arriving on port 8883
can only match routes that say `entryPoints: [mqttwss]`. A connection on port 443 can only
match routes that say `entryPoints: [websecure]`. The port IS the distinguisher.

```
Hetzner server (one node, one Traefik)
  ├── port  80  → Traefik "web" entrypoint        → HTTP (ACME challenge, redirect)
  ├── port 443  → Traefik "websecure" entrypoint  → HTTPS (fall-dashboard, inference server)
  └── port 8883 → Traefik "mqttwss" entrypoint    → WSS MQTT only (mosquitto:9001)
```

---

## Port 1883 — plain TCP MQTT, internal only

```
fall-dashboard pod  ->  mosquitto Service :1883  ->  mosquitto pod :1883
```

- Used exclusively by fall-dashboard to subscribe to `fall/alert/#` and `fall/possible/#`
- Configured in fall-dashboard via `MQTT_BROKER_HOST=mosquitto` (cluster DNS)
- Service type is ClusterIP -- never reachable from outside the cluster
- Plain TCP, no TLS, no WebSocket
- React Native cannot use this (cannot open raw TCP sockets in JS) -- mobile app never touches 1883

---

## Port 9001 — WebSocket MQTT, mosquitto's internal listener

This is mosquitto's WebSocket listener inside the pod. It is always the **destination** port.
External traffic never arrives here directly -- something else (Traefik or kube-proxy) forwards to it.

```
Path A (Traefik via port 443 -- DOES NOT WORK on Traefik v3, see below):
  mobile app -> wss://<domain>:443 -> Traefik websecure -> mosquitto Service :9001 -> mosquitto pod :9001

Path B (Traefik via port 8883 -- WORKS, chosen approach):
  mobile app -> wss://<domain>:8883 -> Traefik mqttwss -> mosquitto Service :9001 -> mosquitto pod :9001

Path C (NodePort workaround -- bypasses Traefik, test only):
  mobile app -> ws://5.75.255.114:30901 -> kube-proxy -> mosquitto Service :9001 -> mosquitto pod :9001
```

**Why port 443 does not work for MQTT on Traefik v3:**
The `websecure` entrypoint (port 443) manages TLS at the entrypoint level for HTTPS. When
IngressRouteTCP is added to `websecure`, Traefik attempts TLS on the backend connection to
mosquitto:9001 as well (because of entrypoint-level TLS behavior). mosquitto:9001 is a plain
WebSocket listener -- it does not speak TLS. Traefik's attempt to read TLS from the backend
fails with `tls: bad record MAC`. Route-level TLS options (certResolver, TLSOption) are ignored
because TLS is managed at the entrypoint level, not the route level.
This is a Traefik v3 limitation specific to the `websecure` entrypoint. Traefik v2 does not
have this behavior.

**Why port 8883 works:**
The `mqttwss` entrypoint is a pure TCP entrypoint -- not an HTTPS entrypoint. TLS is managed
entirely at the IngressRouteTCP route level (certResolver: le). Traefik terminates TLS from the
client, forwards plain TCP to mosquitto:9001. No entrypoint-level TLS conflict.

## Port 8883 — WSS MQTT external entry via Traefik (production path)

```
mobile app -> wss://fall-mqtt.smarko-health.de:8883
  -> Hetzner firewall (port 8883 must be open)
  -> node:8883
  -> Traefik "mqttwss" entrypoint (pure TCP, no HTTPS conflict)
  -> IngressRouteTCP: HostSNI(fall-mqtt.smarko-health.de), certResolver: le
  -> Traefik terminates TLS, passes plain TCP
  -> mosquitto Service :9001
  -> mosquitto pod :9001 (WebSocket listener)
  -> WebSocket upgrade handled by mosquitto
  -> MQTT CONNECT / CONNACK
```

Port 8883 is the IANA-standard port for MQTT over TLS (MQTTS), so this is a meaningful and
expected port for MQTT clients. Isa's mobile app connects to `wss://fall-mqtt.smarko-health.de:8883`.

---

## Port 443 — HTTPS external entry via Traefik (for fall-dashboard and inference server)

```
browser / Flutter dashboard -> https://fall-dashboard.smarkohealth.de:443
  -> Traefik "websecure" entrypoint
  -> IngressRoute: Host("fall-dashboard.smarkohealth.de")
  -> fall-dashboard Service :8002
  -> fall-dashboard pod
```

Port 443 is HTTPS only. MQTT WebSocket does NOT go through port 443 in the Hetzner/FOCUS
production setup (Traefik v3 limitation explained above).

---

## Port 30901 — NodePort (Hetzner test workaround only)

```
mobile app -> ws://5.75.255.114:30901 -> kube-proxy (OS iptables) -> mosquitto :9001
```

- Bypasses Traefik entirely
- Plain WebSocket, no TLS
- Used only to test external connectivity without Traefik in the path
- NOT used in FOCUS production (mosquitto stays ClusterIP behind Traefik on port 8883)

## Summary table

| Port | Where | Used by | Protocol | Notes |
|------|-------|---------|----------|-------|
| 1883 | Inside cluster only | fall-dashboard pod | Plain TCP MQTT | ClusterIP, never external |
| 9001 | Inside mosquitto pod (destination) | Traefik (forwards to it) + kube-proxy | WebSocket MQTT | Never directly reachable externally |
| 8883 | Host NIC (Traefik mqttwss entrypoint) | Mobile app (production) | WSS — Traefik terminates TLS, forwards plain TCP to 9001 | Standard MQTTS port |
| 443  | Host NIC (Traefik websecure entrypoint) | Browser, Flutter dashboard | HTTPS | MQTT does NOT go through 443 on Traefik v3 |
| 30901 | Host NIC (NodePort) | Mobile app (test workaround only) | Plain WS (no TLS) | Bypasses Traefik |

Port 9001 is never directly reachable from outside -- it is always the internal target
that Traefik or kube-proxy forwards to.
