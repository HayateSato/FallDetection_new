The system is composed of three layers in a big picture
 1. Patinet layer
 2. Backend layer
 3. Caregiver front-end
 4. Post-training front-end

Subcompoenents in each layer is hosted either in 
 (F): FOCUS network
 (M): MCS network


1. Patient layer
-----------------------------------------------------------------------------------------------
- SmarKo                    (F)         collecting physiological data and sends to mobile app
- mobile app                (F)         transmits the collected data to influxDB 
                                        directly POST request to inference API to detect a fall
                                        displays fall confirmation popup and alert caregive if confirmed & injects the marker into influxDB 
- MQTT client_1             (F)         publishes event (help needed) to web app server

2. Caregiver Backend layer
-----------------------------------------------------------------------------------------------
- FHIR server               (F)         stores demographic infomration of patients 
- influxDB                  (F)         stores physiological infomration of patients
- postgres                  (F)         stored user (caregiver)/session infomration 
                            (M)         stores inference api server log
                            (M)         stores input data used during inference
                            (M)         stores retained model information 
- minIO                     (M)         stores model artifacts (old models) and its path
- infrence server           (M)         API server for fall detection, talks to mobile app 
- MQTT broker               (F)         infrastructure for MQTT protocol 
- MQTT client_2             (F)         event subscriber and expose the event to web app server 
- mlflow                    (M)         manages ml model lifecycle 
- grafana                   (M)         monitoring server for ml health performance
- promotheus                (M)         scrapes all the health data of ml inference server and model drift
- caregiver webapp server   (F)         backend component for caregiver web app 
- post-trning webapp server (F)         backend component for caregiver web app 


3. Caregiver front-end
-----------------------------------------------------------------------------------------------
- caregiver webapp server 
  - patinet dashboard       (F)         displays registered patients and their personal information (gender, BMI etc.) and health monitoring status (HR, SpO2 etc.)
                                        in the event of a fall, it should indicate which patient has fallen  
  - fall dashboard          (F)         displays all the falls, can be filited by period, patient, whether help requetsed or not

4. Post-training front-end
-----------------------------------------------------------------------------------------------
- post-trning webapp server
  - ml dashbord             (M)         frontend for admin user to retrain models and hot-swap 
  - server health dashbaord (M)         monitoring server performance
  - grafana dashboard       (M)         monitoring ml model performance
