# MQTT Connection Tests

Use these commands to verify the broker is working correctly at each stage of the deployment.

---

### Test MQTT publish/subscribe from inside the cluster

Use `mosquitto_pub` and `mosquitto_sub` tools that are included in the `eclipse-mosquitto:2` image.

Open two terminals.

**Terminal 1 — subscribe (listen for messages):**

```bash
kubectl exec -n fall-dashboard deploy/mosquitto -- \
  mosquitto_sub -h localhost -p 1883 -t "fall/alert/#" -v
```

**Terminal 2 — publish a test message:**

```bash
kubectl exec -n fall-dashboard deploy/mosquitto -- \
  mosquitto_pub -h localhost -p 1883 \
    -t "fall/alert/patient_test" \
    -m '{"patient_id":"patient_test","fall_detected":true}'
```

Terminal 1 should immediately print the message. If it does not, the broker is not routing
messages correctly — check the broker logs.

---

### Test WebSocket connectivity from outside (verify Traefik routing)

The simplest check is a plain HTTPS request to the broker domain. A 400 Bad Request with
"websocket upgrade required" is the correct response — it means Traefik reached the pod:

```bash
curl -v https://mqtt.focus-hospital.de
# A 4xx response from mosquitto means routing is working.
# A connection refused or timeout means Traefik is not routing to the pod.
```

For a full WebSocket test, use `mosquitto_sub` with the WebSocket flag from a machine
outside the cluster (requires `mosquitto-clients` installed):

```bash
mosquitto_sub -h mqtt.focus-hospital.de -p 443 --cafile /etc/ssl/certs/ca-certificates.crt \
  -t "fall/alert/#" -v
# On newer mosquitto-clients, use: --url wss://mqtt.focus-hospital.de
```

### Restart the broker (e.g. after config change)

```bash
kubectl rollout restart deployment/mosquitto -n fall-dashboard

# Wait for the new pod to be ready
kubectl rollout status deployment/mosquitto -n fall-dashboard
```

> After a restart, the fall-dashboard pod will reconnect automatically (it retries with
> backoff). Allow up to 30 seconds. Verify reconnect with the SUBSCRIBE log check above.

---

### Describe the pod (for scheduler/image/volume errors)

```bash
kubectl describe pod -n fall-dashboard -l app=mosquitto
```

---

### Check the ConfigMap (verify your mosquitto.conf was applied)

```bash
kubectl get configmap mosquitto-config -n fall-dashboard -o yaml
```

---

### Apply a values change without full reinstall

```bash
helm upgrade caregiver helm/ \
  --namespace fall-dashboard \
  --values helm/values_production.yaml
```
